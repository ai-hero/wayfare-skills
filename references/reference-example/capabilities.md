# Capability map

What the library must be able to do, not how. The stages in
`value-streams/lend-a-tool.md` point here by id.

| Id | Capability | Definition | Owner | Systems today | Heat |
| -- | -- | -- | -- | -- | -- |
| C1 | **Catalog** |  | coordinator |  |  |
| C1.1 | Tool discovery | knowing which tools exist and which are free | coordinator | a printed list on the wall | weak |
| C2 | **Lending** |  | desk volunteers |  |  |
| C2.1 | Reservation and checkout | holding a tool for a member and recording the loan | desk volunteers | the paper hold book | weak |
| C2.2 | Returns | taking a tool back and closing its loan | desk volunteers | the paper hold book | adequate |
| C3 | **Upkeep** |  | repair volunteers |  |  |
| C3.1 | Condition tracking | knowing whether each tool works | repair volunteers | memory and sticky notes | weak |

Heat is how well the capability works today: `strong`, `adequate` or `weak`. It
is a hypothesis, like the stream.
